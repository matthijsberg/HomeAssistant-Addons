# Knowledge Index — Hermes Agent Add-on

This bundle records the normative architecture, security boundaries, and operating
rules of the **Hermes Agent Home Assistant add-on** (fork of
`WolframRavenwolf/hermes-ha-addon`). Concepts are agent-consumable: Hermes itself can
read them before changing its own add-on. Changes are recorded in [`log.md`](log.md);
user-facing release notes stay in `CHANGELOG.md`.

Concepts generated by an agent carry `trust: unverified` until a human reviews them
and promotes them to `human_reviewed`.

## 1. Architecture Contracts
- [`upstream-lineage`](architecture/upstream_lineage.md) — Fork base, ported upstream releases, intentional divergences, and the sync procedure.
- [`gateway-supervision`](architecture/gateway_supervision.md) — One supervised gateway slot per profile: handoff, readiness, containment, restart, logging.
- [`python-runtime`](architecture/python_runtime.md) — Shared install, `.python-version` pin, venv rebuild rules, and coexistence with self-managed Hermes.
- [`profile-topology`](architecture/profile_topology.md) — Profile resolution, HA user sync, port/prefix allocation, standalone profiles, channel isolation.

## 2. Security
- [`access-boundaries`](security/access_boundaries.md) — Auth per entry point, credential rules, secret file modes, known gaps.

## 3. Operations
- [`backups`](operations/backups.md) — HA backup exclusions, Hermes pre-update backups, periodic archives, manual backups.

## 4. Integrations
- [`home-assistant`](integrations/home_assistant.md) — Token/URL resolution, MCP tool injection, status sensors, bundled skill.
