1. Ongedefinieerd Verbruik (7×96 + Seizoen) EMBEDDED KERNEL
P_unalloc(t) = max(P_floor, S_dow,tod · (1.0 + A · cos(2π · (d - 15) / 365.25)))
  • P_floor: 265.0 W (20e-percentiel nachtbaseload).
  • A (Seizoensamplitude): 22% hogere baseline in januari dan in juli.
  • S_dow,tod: 7×96 kwartieren matrix geleerd uit 374 dagen data.
2. CV Ruimteverwarming (2R1C Gebouwmodel) THERMISCH VERLIES
Q_cv(t) = (UA_base + c_wind · v_wind) · (T_binnen - T_buiten) - c_zon · G_zon
  • UA_base: 321.1 W/K (7.71 kWh/°C/dag isolatiegraad).
  • Nachtverlaging: 20.0°C overdag · 17.5°C tussen 23:00 en 06:00.
  • Zomeruitschakeling: Uitgeschakeld bij dagtemperatuur ≥ 16.0°C.
3. Daikin Warmtepomp Carnot COP Curve THERMODYNAMISCH
COP(t) = η_carnot · (T_flow + 273.15) / (T_flow - T_buiten) · f_defrost
  • η_carnot: 0.48 (gekalibreerd op Daikin Altherma 3 H HT 18kW).
  • T_flow CV: 35.0°C vloerverwarming aanvoer.
  • f_defrost: 18% COP-straf tussen -2°C en +4.5°C bij hoge vochtigheid.
4. SWW Tapwaterboiler (350 Liter Combivat) MASSA BALANS
Q_sww = [V · c_p · (T_doel - T_inlaat)] / 3600 + Q_stilstand
  • Volume: 350 liter vat · doel 50.0°C (6.2 à 7.5 kWh_th / dag).
  • DHW COP: ~2.7 in winter, 3.2 in zomer (aanvoer 52°C).
  • Dispatch Window: 3 opeenvolgende kwartieren (45 min) rond zonnepiek.

def predict_unallocated_w(dt: datetime) -> float:
    dow = dt.weekday()
    q_idx = dt.hour * 4 + dt.minute // 15
    base_w = profile_96_quarters[dow][q_idx]
    seasonal_mult = 1.0 + 0.22 * math.cos(2.0 * math.pi * (dt.timetuple().tm_yday - 15) / 365.25)
    return max(265.0, round(base_w * seasonal_mult, 1))

def predict_space_heating_w(dt: datetime, t_outdoor_c: float) -> dict:
    if t_outdoor_c >= 16.0 or dt.month in [6, 7, 8]:
        return {"electrical_w": 0.0, "thermal_w": 0.0, "cop": 0.0}
    t_target = 17.5 if (dt.hour < 6 or dt.hour >= 23) else 20.0
    q_thermal_w = max(0.0, 321.1 * (t_target - t_outdoor_c))
    cop = calculate_cop(t_flow=35.0, t_outdoor=t_outdoor_c)
    return {"electrical_w": round(q_thermal_w / cop, 1), "cop": cop}

1. Systeemarchitectuur (Clean Architecture / 5 Lagen)

Strikte scheiding van dataverzameling, fysische modellen, centrale besluitvorming, hardware aansturing en presentatie.

Core Invariants
Laag 1 · Data Ingestion

TelemetrySanitizer valideert ruwe data uit P1, zonne-omvormer en sensoren. Fysische bounds checks, 15m grid-alignment en TTL-waakhonden. Geen vuile data naar boven.

Laag 2 · Kalibratie & Fysica

DhwThermalModel (350L tank, 0.407 kWh/K, 59W stilstandsverlies) en 2R1C gebouwmodel voor vloerverwarming. Voorspelt afkoeling en warmtevraag.

Laag 3 · Centrale Dispatch

CentralPlanner & PlanStore. Single Source of Truth. Berekent 24h kwartierschema, marktarbitrage en dynamische spitsblokkades.

Laag 4 · Actuators & Interlocks

Apparaatspecifieke adapters (DaikinAlthermaActuator). Beheert relais, hardware dwell-times (120m herstel), noodvergrendelingen en rapporteert effective_mode terug.

Laag 5 · Presentatielaag

Domme Views. Geen berekeningen of thermodynamica in de GUI. Leest en schrijft uitsluitend via de gestandaardiseerde REST API.

🛡️ De 5 Onschendbare Architectuurinvariants (Core Invariants)
1. Single Source of Truth: Alle grafieken en actuatoren lezen hetzelfde plan uit de PlanStore. Nooit afzonderlijke berekeningen in views.
2. Core Entity Isolation: Geen Home Assistant entiteitsstrings of merknamen in de rekenkern. Alles configureerbaar via adapters en site config.
3. Strikte No-Mock Directive: Geen gefabriceerde data in productie. Reële metingen uit InfluxDB/HA of replay-snapshots in tests.
4. Hardware Circuit Breakers: Spitsblokkade (max 150m) en dwell-times (min 120m) worden op relaisniveau hardwarematig afgedwongen.
5. API & MCP Lockstep Parity: Elke toevoeging of wijziging in de REST API wordt direct vastgelegd in docs/openapi.json en gelijktijdig ontsloten via de MCP Server (mcp_server.py). De geautomatiseerde test test_api_mcp_lockstep.py bewaakt 100% pariteit.

2. Sturingslogica & Beslisbomen

Hoe Open HEMS beslist over spitsblokkades, nachtelijk boiler laden, dagelijkse zonne-arbitrage en vloerverwarming.

Decision Engine
A. Dynamische Spitsblokkade (forced_off / SG1) Prioriteit 1 (Harde Regel)

Schakelt de warmtepomp volledig uit tijdens extreme beursprijzen via Smart Grid contact 1 (SG1).

  • Marktvensters: Uitsluitend actief in Ochtendspits (06:00–10:00) en Avondspits (17:00–21:00).
  • Drempel: Kwartierprijs ≥ P75/P85 van de dag én minimaal €0,035/kWh boven daggemiddelde.
  • Harde Cap: Maximaal 150 minuten (2,5 uur) aaneengesloten per spitsblok.
  • Dwell-Time: Minimaal 120 minuten normale werking na afloop van een blokkade.
  • Onbreekbaar: Kan onder geen beding worden overschreven door warmtevraag of zonne-adviezen.
B. Nachtelijk Boiler Laden (forced_on / SG2) Prioriteit 3

Zorgt dat het 350L vat op 50°C is vóór de ochtendspits begint (venster 20:00–06:00).

  • Comfort-Trigger: Alleen actief als de gesimuleerde ochtenddip < 40°C zakt (comfortrisico). Blijft de dip ≥ 40°C, dan zijn de nachtkosten exact €0,00.
  • Dynamische Runduur: N = Math.ceil(0.407 × (50 - T_tank) / 1.63) kwartieren (bij 6,5 kWth compressorvermogen).
  • Stilstandsverlies: 59W continu verlies (∼0,059 kWh/h) wordt meegewogen: vroeg laden krijgt een kostenboete voor de verloren uren.
  • COP-optimalisatie: COP = 2.55 + 0.075 × T_buiten. Laagste all-in netstroomvenster wint.
C. 24u Dagplanning & Zonnebuffer (max_on / SG4) DhwDaytimeArbiter

Zuivere economische vergelijking over 24 uur tussen 50°C basislading en 60°C zonnebuffer. Geen arbitraire drempels.

  • Situatie 1 (Avondcomfort in gevaar): Pad A1 (overdag 50°C + gesimuleerde nachtrun) vs Pad A2 (overdag direct door naar 60°C). Goedkoopste totale 24-uurs pad wint.
  • Situatie 2 (Avondcomfort veilig): Pad B1 (Standby) vs Pad B2 (Economisch bufferen naar 60°C als zonne/beursstroom goedkoper is dan de vermeden nachtrun).
  • Exclusiviteit: max_on (60°C) mag uitsluitend door DHW worden ingezet. Ruimteverwarming kan nooit naar max_on.
D. Vloerverwarming Pre-Heat (advised_on / SG3) 2R1C Thermal Model

Benut de 3 tot 4 uur thermische traagheid van de dekvloer om dure spitsblokkades comfortabel te overbruggen.

  • Pre-Heat Nachtdal: Laadt de dekvloer licht voor tijdens de goedkoopste nachturen vóór de ochtendspits (04:00–06:00).
  • Zomerstop: Automatisch uitgeschakeld zodra de buitentemperatuur ≥ 16°C bereikt.
  • Interlock: CV schakelt fysiek uit wanneer DHW tapwater opwarmt (Daikin 3-wegklep prioriteit).

5. Gestandaardiseerde REST API Referentie (OpenAPI 3.1.0)

Industriestandaard specificatie. Alle endpoints zijn ontkoppeld, stateless en JSON-geserialiseerd.

schema
GET /api/schedule/chart-data
Tag: Schedule & Dispatch

Haalt de centrale 24-uurs kwartier-dispatch tijdlijn op. Bevat de geplande werkmodi (forced_off, normal, forced_on, max_on), marktprijzen, zonnevoorspelling en stroomkosten per kwartier.

Query Params: resolution=15m|1h Response: 200 OK (application/json)
GET /api/model/dhw-status
Tag: Models & Thermodynamics

Geeft de actuele 350L tanksensortemperatuur (°C), het gesimuleerde temperatuurtraject (verwarmd vs onverwarmd referentieprofiel), de verwachte thermische warmtevraag in kWh_th en V40 liters mengwater, en de 24u dagplanning-arbitrage.

Query Params: resolution=15m|1h Response: 200 OK (application/json)
GET /api/analytics/dhw_history
Tag: Analytics & History

Haalt gerealiseerde historische tanksensortemperaturen (°C) en geleverde thermische warmte (kWh_th) op uit de openhems InfluxDB database over een configureerbaar tijdvenster.

Query Params: range=24h|48h|7d, resolution=15m|1h Response: 200 OK (application/json)
GET /api/analytics/power_producers
Tag: Analytics & History

Tijdreeks van elektrisch vermogen (kW) en energie (kWh) voor zonnepanelen, warmtepomp, P1 afname/teruglevering en direct eigenverbruik.

Query Params: range=1h|6h|24h|48h|7d, resolution=15m|1h Response: 200 OK (application/json)
GET /api/analytics/decisions
Tag: Audit & Observability

Volledig chronologisch beslis-logboek. Geeft inzicht in de exacte fysische sensortoestanden, EPEX-tarieven en de wiskundige/financiële motivatie waarom een bepaalde modus is gekozen.

Query Params: limit=50, offset=0 Response: 200 OK (application/json)
GET POST /api/devices
Tag: Devices & Actuators

Beheer van alle geregistreerde apparaten. GET leest de actieve hardwarecatalogus en hun status. POST registreert of wijzigt een apparaat en diens capabilities.

Payload: {device_id, name, capabilities, ...} Response: 200 OK / 201 Created
POST /api/schedule/recalculate
Tag: Schedule & Dispatch

Dwingt een onmiddellijke herberekeningscyclus af in Laag 3 (CentralPlanner) en publiceert een geüpdatet dispatch plan naar de PlanStore.

Payload: Geen (lege POST) Response: 200 OK {"status": "recalculated"}
GET /api/openapi.json
Tag: System & Schema

Serveert de volledige machine-leesbare OpenAPI 3.1.0 JSON-specificatie voor geautomatiseerde client-generatie, validatie of integratie in Swagger/Postman.

Download: openapi.json Response: 200 OK (application/json)

5B. Model Context Protocol (MCP) Server & AI Integratie

Directe koppeling voor AI-assistenten (Hermes Agent, Claude Desktop, Cursor) met strikte lockstep API-pariteit.

stdio & SSE Transports

De Open HEMS MCP Server (mcp_server.py) bouwt direct voort op de gestandaardiseerde OpenAPI 3.1.0 laag. Hierdoor kan elk AI-model autonoom energiestromen inspecteren, beslissingen verifiëren en herberekeningen triggeren zonder dat de architectuur divergeert.

🔒 Het Lockstep Architectuurprincipe (100% API ↔ MCP Pariteit)

Om drifting te voorkomen, bewaakt de geautomatiseerde test tests/architecture/test_api_mcp_lockstep.py dat elk endpoint in docs/openapi.json direct beschikbaar is in MCP. Bovendien bevat de server het gereedschap openhems_call_api_endpoint, waarmee ook toekomstige endpoints onmiddellijk kunnen worden aangeroepen.

Beschikbare MCP Gereedschappen (Tools)

openhems_get_schedule(resolution)

24-uurs dispatch plan, toegekende SG-modi, beurstarieven en stroomkosten.

openhems_get_dhw_status(resolution)

350L tanksensortemperatuur, thermische warmtevraag (kWh_th & V40) en dagplanning.

openhems_recalculate_schedule()

Dwingt onmiddellijke herberekening af in Laag 3 (CentralPlanner).

openhems_get_heating_forecast(resolution)

CV 2R1C gebouwmodel vooruitblik, warmteverlies en pre-heat adviezen.

openhems_get_analytics_power(range, res)

Historische vermogensstromen (zon, warmtepomp, P1 afname/teruglevering).

openhems_get_analytics_dhw(range, res)

Historische tanksensortemperatuur (°C) en geleverde warmte (kWh_th).

openhems_get_decisions(limit, offset)

Volledige audit-trail van beslissingen met fysische en financiële motivatie.

openhems_get_system_health()

Verifieert Single Source of Truth status en pipeline accumulator gezondheid.

Configuratie voor AI Clients (Hermes Agent / Claude Desktop / Cursor): JSON

  "mcpServers": {
    "openhems": {
      "command": "python3",
      "args": ["/config/addons/open-hems/mcp_server.py", "--transport", "stdio"],
      "env": {
        "OPENHEMS_BASE_URL": "http://172.30.33.10:8099"
      }
    }
  }
}
